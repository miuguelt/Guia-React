Hola Mundo en React

Tu primer componente funcional renderizado en el DOM.

¿Que es un componente?

Una funcion que retorna JSX (HTML-like). Es la unidad basica de React: reutilizable y composicional.

¿Que es JSX?

Sintaxis que parece HTML pero vive dentro de JavaScript. Permite mezclar logica y vista en un mismo archivo.

¿Que es export default?

Hace que el componente pueda ser importado en otro archivo. main.jsx importa App y lo renderiza.

Expresiones en JSX

04

Estado con useState y useEffect

Datos que cambian en el tiempo y efectos secundarios controlados.

useState: datos reactivos

Cuando el estado cambia, React re-renderiza el componente automaticamente. No necesitas manipular el DOM manualmente.

useEffect: sincronizar con el mundo exterior

Se ejecuta despues del render. Ideal para consumir APIs, suscripciones, timers.

Array de dependencias vacio []: significa "ejecutar solo una vez, al montar el componente". Si lo omites, el efecto se ejecuta en CADA render, causando un loop infinito de peticiones a la API.

Consumo de APIs con Fetch

Patron loading/error/empty state para consumo robusto de APIs.

Custom Hook: useApi

Encapsulamos la logica de consumo para reutilizarla en todos los componentes.

Tres estados, tres vistas

⏳

Loading

if (loading)
  return <Spinner />

El usuario sabe que algo pasa. Nunca dejes la pantalla en blanco.

⚠

Error

if (error)
  return <ErrorBox
    mensaje={error}
    onRetry={refetch}
  />

Muestra el error y ofrece reintentar. El usuario no debe sentirse atrapado.

📄

Empty

if (data.length === 0)
  return <EmptyState
    mensaje="Sin fincas"
    action="Crear"
  />

Lista vacia no es error. Ofrece una accion clara: crear, importar, etc.

Servicio API centralizado

Patron centralizado: Todas las llamadas a la API pasan por request(). Si necesitas cambiar la URL base, agregar autenticacion o manejar tokens, lo haces en UN solo lugar.

Construccion paso a paso del frontend que consume la API del dominio Finca-Cultivo.

Regla pedagogica N:M: Cada vez que veas la relacion muchos a muchos, recuerda: NO basta una llave foranea simple. Una FK en Finca apuntando a Cultivo solo permitiria UN cultivo por finca. Una FK en Cultivo apuntando a Finca solo permitiria UNA finca por cultivo. La tabla intermedia FincaCultivo resuelve ambos problemas y ademas almacena atributos propios de la relacion (area, fecha, temporada).

6.4 Vista de Detalle de Finca (sus cultivos con atributos propios)

src/components/FincaDetalle.jsx 
import { useState, useEffect } from 'react'
import { api } from '../services/api'

function FincaDetalle({ fincaId, onVolver }) {
  const [finca, setFinca] = useState(null)
  const [cultivosAsociados, setCultivosAsociados] = useState([])
  const [loading, setLoading] = useState(true)
  const [filtroEstado, setFiltroEstado] = useState('todos')

  useEffect(() => {
    Promise.all([
      api.fincas.getById(fincaId),
      api.fincaCultivo.getByFinca(fincaId)
    ])
      .then(([f, cultivos]) => { setFinca(f); setCultivosAsociados(cultivos) })
      .catch(console.error)
      .finally(() => setLoading(false))
  }, [fincaId])

  const cultivosFiltrados = filtroEstado === 'todos'
    ? cultivosAsociados
    : cultivosAsociados.filter(c => c.estado === filtroEstado)

  if (loading) return <div className="spinner">Cargando detalle...</div>
  if (!finca) return <div className="error-box">Finca no encontrada</div>

  return (
    <div className="finca-detalle">
      <button onClick={onVolver} className="btn-back">← Volver</button>

      <div className="finca-header">
        <h2>{finca.nombre}</h2>
        <p>{finca.propietario} — {finca.vereda}, {finca.municipio}</p>
        <p>{finca.hectareas} hectareas en total</p>
      </div>

      <div className="filtro-bar">
        <span>Filtrar:</span>
        {['todos', 'activo', 'cosechado'].map(est => (
          <button key={est}
            className={`filtro-btn ${filtroEstado === est ? 'active' : ''}`}
            onClick={() => setFiltroEstado(est)}>
            {est === 'todos' ? 'Todos' : est.charAt(0).toUpperCase() + est.slice(1)}
          </button>
        ))}
      </div>

      <h3>Cultivos asociados ({cultivosFiltrados.length})</h3>

      {cultivosFiltrados.length === 0 ? (
        <div className="empty-state">
          Esta finca no tiene cultivos {filtroEstado !== 'todos' ? filtroEstado : 'registrados'}.
        </div>
      ) : (
        <div className="cultivos-grid">
          {cultivosFiltrados.map(fc => (
            <div key={`${fc.finca_id}-${fc.cultivo_id}`} className="cultivo-card">
              <div className="cultivo-card-header">
                <h4>{fc.cultivo_nombre}</h4>
                <span className={`badge badge-${fc.estado}`}>{fc.estado}</span>
              </div>
              <div className="cultivo-card-body">
                <p><strong>Area:</strong> {fc.area_sembrada_ha} ha</p>
                <p><strong>Siembra:</strong> {fc.fecha_siembra}</p>
                <p><strong>Temporada:</strong> {fc.temporada}</p>
              </div>
            </div>
          ))}
        </div>
      )}
    </div>
  )
}

export default FincaDetalle
Nota los atributos propios: En el detalle NO solo mostramos el nombre del cultivo. Mostramos area_sembrada_ha, fecha_siembra y temporada — datos que viven en la tabla intermedia FincaCultivo, no en Cultivo. Esto es exactamente lo que justifica la tabla intermedia.

07

UX: Visualizar N:M en la Interfaz

Por que mostrar una relacion N:M con atributos propios es distinto a una simple lista, y como hacerlo claro para usuarios con baja alfabetizacion digital.

El problema: la N:M es invisible para el usuario

El usuario final no sabe que existe una tabla intermedia. Solo ve "la finca tiene cultivos". Pero como desarrolladores, debemos decidir COMO mostrar esa relacion para que sea clara y util.

❌ Mal: Lista plana

Finca El Porvenir:

  • Cafe
  • Maiz
  • Frutales

Problema: El usuario no sabe CUANTA tierra tiene cada cultivo, ni cuando se sembro, ni en que temporada. Se perdieron los atributos propios de la relacion.

✅ Bien: Cards con contexto

Finca El Porvenir (8.5 ha):

Cafe 3.2 ha | Mar 2026 | Lluvia
Maiz 2.0 ha | Ene 2026 | Seca

Cada card muestra el cultivo + los datos de ESA siembra especifica (area, fecha, temporada). El usuario entiende la relacion completa.

Principios UX para usuarios campesinos

👁

Visibilidad del estado

Muestra siempre que esta pasando: "Cargando...", "Guardado", "Error al conectar". El usuario no debe adivinar.

💬

Lenguaje del usuario

No digas "registro creado exitosamente". Di "Cultivo asociado a la finca". Usa terminos del dominio agricola, no tecnicismos de base de datos.

⚠

Prevencion de errores

Antes de eliminar, pregunta "¿Eliminar esta asociacion?". Antes de asociar un cultivo que ya existe, muestra advertencia. Los selects ayudan mas que los inputs de texto libre.

📱

Diseno mobile-first

Muchos usuarios acceden desde celular. Las tablas deben ser scrollables horizontalmente. Los formularios deben ser de una sola columna en movil. Los botones deben ser grandes y faciles de tocar.

🔄

Tolerancia a conexion intermitente

Si la conexion falla, no pierdas los datos del formulario. Guarda borradores en localStorage. Muestra un mensaje claro y permite reintentar sin re-llenar todo.

Patron recomendado: Vista Jerarquica

Estructura de navegacion UX 
Lista de Fincas (tabla simple)
  └── Click en "Ver cultivos" → Detalle de Finca
        ├── Info de la finca (nombre, propietario, hectareas)
        ├── Filtros: Todos | Activos | Cosechados
        └── Grid de cards de cultivos asociados
              ├── Nombre del cultivo
              ├── Area sembrada (atributo de la relacion)
              ├── Fecha de siembra (atributo de la relacion)
              ├── Temporada (atributo de la relacion)
              └── Estado: activo/cosechado (atributo de la relacion)
La clave: El usuario nunca ve la tabla FincaCultivo directamente. Ve "los cultivos de esta finca" con sus datos especificos. La N:M se traduce a una experiencia natural: "esta finca tiene estos cultivos, cada uno con su area y fecha".

Terminal 3 — Pruebas

  -H "Content-Type: application/json" \
  -d "{\"nombre\":\"El Porvenir\",\"propietario\":\"Jose Rodriguez\",\"vereda\":\"La Mesa\",\"municipio\":\"Velez\",\"hectareas\":8.5}"

# 2. Crear un cultivo
curl -X POST http://localhost:8009/api/cultivos \
  -H "Content-Type: application/json" \
  -d "{\"nombre\":\"Cafe\",\"tipo\":\"Cafe\",\"ciclo_dias\":180}"

# 3. Asociar cultivo a finca (N:M)
curl -X POST http://localhost:8009/api/finca-cultivo \
  -H "Content-Type: application/json" \
  -d "{\"finca_id\":1,\"cultivo_id\":1,\"area_sembrada_ha\":3.2,\"fecha_siembra\":\"2026-03-15\",\"temporada\":\"lluvia\"}"

# 4. Listar cultivos de una finca
curl http://localhost:8009/api/fincas/1/cultivos
